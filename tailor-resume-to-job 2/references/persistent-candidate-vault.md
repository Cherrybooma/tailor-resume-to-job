# 持久化候选人资料库

## 目标

让同一候选人在更换目标岗位 JD 时复用已经确认的事实和材料，不必重复上传主简历、论文、作品集或报告。资料库必须位于 Skill 文件夹之外，并由用户明确同意启用。

## 推荐目录结构

```text
resume-vault/<candidate-id>/
├── vault.json
├── candidate-profile.json
├── evidence-index.json
├── evidence/
├── derived/
└── applications/
```

资料库根目录同时保存 `vault-index.json`，记录候选人 ID、姓名和资料库路径，便于新任务定位。存在多名同名候选人时仍需通过联系方式或用户确认区分。

- `vault.json`：资料库版本、候选人 ID、姓名和更新时间。
- `candidate-profile.json`：结构化个人事实及确认状态。
- `evidence-index.json`：每份来源的类型、稳定路径、SHA-256、保存方式和更新时间。
- `evidence/`：经用户同意复制保留的主简历、论文、证书、报告或作品。
- `derived/`：从材料提取的可重建文本或结构化摘要；不得替代原始证据。
- `applications/`：可选的 JD 分析和简历版本索引，不复制无必要的中间文件。

## 初始化与查找

- 优先使用用户指定的资料库路径。
- 没有指定时，在稳定且跨任务可访问的工作区目录下使用 `resume-vault/<candidate-id>`；创建前必须获得用户同意。
- 候选人 ID 使用稳定的短标识，不在公开文件名中加入身份证号等敏感信息。
- 再次使用时根据用户姓名、联系方式或明确指定的候选人 ID 定位资料库；存在多个候选人时不得猜测。

## 保存来源

- 使用 `scripts/candidate_vault.py init` 初始化。
- 使用 `scripts/candidate_vault.py add-source` 登记来源。
- 小型、稳定、用户允许长期保存的文件可选择 `copy`；大代码仓库、受限材料或已有稳定路径的文件优先选择 `reference`。
- 按 SHA-256 去重，不覆盖已保存文件。源文件发生变化时新增版本，不静默替换旧证据。
- 对论文、作品或团队交付物，记录材料能证明的事实与候选人个人贡献之间的区别。

## 更新事实

- 新材料和用户回答只做增量合并。
- `confirmed` 事实默认保留；用户明确纠正时记录新来源和更新时间。
- `draft`、`ambiguous` 和 `conflicting` 事实不得在不同 JD 之间悄然升级为已确认。
- 每次简历任务结束时，说明新增了哪些来源、确认了哪些事实、保留了哪些待确认问题。

## 隐私与可控性

- 不把候选人资料存入 Skill 安装目录。
- 不自动保存访问令牌、未脱敏客户数据、商业秘密或用户未授权保留的附件。
- 用户可以要求查看、迁移、停止更新或删除资料库；删除属于破坏性操作，执行前确认精确路径和范围。
- 资料库是本地文件目录，不是云服务；只有当前环境有权限读取时才能跨任务复用。
