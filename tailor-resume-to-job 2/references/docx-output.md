# DOCX 输出规则

将已安装的 `documents` Skill 作为 Word 工作流的权威规范。开始制作前，先加载工作区提供的 Python 运行环境。

## 判断输入方式

- 需要保留版式时，优先使用主简历 DOCX。
- 主简历含照片时，默认保留照片并读取 `references/resume-template-and-photo.md`。
- 除非用户接受重新构建版式，否则 PDF 只用于提取内容。
- 对结构稳定的源 DOCX 进行最小范围的局部修改。
- 当源文件包含不稳定的文本框、浮动对象或混乱的阅读顺序，但用户重视视觉质量或主简历含照片时，改用 `assets/professional-resume-cn.docx`。
- 只有用户明确要求 ATS 极简版、目标渠道禁止照片或专业模板不适用时，才改用内置 ATS 模板。

## ATS 优先版式

- 使用单一主要阅读栏。
- 将所有重要信息保留为真实文本。
- 使用常规简历模块标题。
- 不把关键联系方式放在页眉或页脚中。
- 不使用图标代替文字标签。
- 不使用技能进度条、图表、装饰形状和嵌套表格。
- 只有短内容对齐且阅读顺序清晰时才使用表格；优先使用制表位和段落。
- 使用能够覆盖中文和拉丁字符的标准字体。
- 保持正文易读；优先删除低价值内容，不要把字号缩小到 9.5 磅以下。
- 在保持文本提取顺序完整的前提下对齐日期和地点。

## 选择模板

- 中文专业视觉版使用 `assets/professional-resume-cn.docx`，并按需替换其中的 `[[PHOTO]]`。
- 中文 ATS 极简版使用 `assets/ats-resume-cn.docx`。
- 英文 ATS 极简版使用 `assets/ats-resume-en.docx`。
- 将占位文字视为结构示例。替换所有占位文字，并删除没有使用的模块。
- 保留模板样式，不要用零散的直接格式重新模拟模板。

## 编辑和渲染

1. 将源文件或模板复制到新的输出路径。
2. 使用 `python-docx` 编辑，并保留样式和页面设置。
3. 只有处理不受 `python-docx` 支持的功能时才使用 OOXML。
4. 在 macOS 上使用稳定的临时目录，并通过 `documents` Skill 的 `render_docx.py` 渲染。
5. 以 100% 缩放检查每一张 PNG 页面图片。
6. 修复内容溢出、文字裁切、孤立标题、经历条目拆页、缺字、字体替换和留白不均。
7. 重复渲染和检查，直到全部页面正常。

## 一页版面校准

- 学生、应届生和工作经验较少的候选人默认输出恰好一页。
- 最后一个有效模块应自然结束在底部安全边距之上；不要留下明显大块空白，也不要贴住页脚或发生溢出。
- 内容不足时，先补充有证据的项目方法、实验、验证和结果，再增加相关论文、专利或成果；最后才微调段落间距、行距和字号。
- 内容过多时，先删除低相关和重复内容，再压缩措辞与间距。正文不得小于 9.5 磅。
- 每次调整后重新渲染并检查完整页面，不得仅凭页数判断“刚好一页”。

如果 macOS 上的中文字符被渲染成空方框，而 DOCX 本身结构正常，将 `FONTCONFIG_FILE` 指向 `scripts/fontconfig-macos.xml` 后重新渲染。这只用于修复渲染器发现字体的问题；DOCX 仍使用 Microsoft YaHei 等常见中文 Word 字体，并且必须检查字体回退后的页面效果。

## 干净交付

- 默认交付 DOCX。
- 删除批注、修订记录、占位文字、隐藏备注和临时事实 ID。
- 保持文件可以继续编辑。
- 使用 `<候选人>_<公司>_<岗位>_<YYYYMMDD>.docx`，并删除文件名中不安全的字符。
- 只有用户要求时才提供 PDF 或带修订的审阅版。
